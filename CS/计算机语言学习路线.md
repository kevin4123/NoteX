# C/C++ 项目驱动进阶路线（Tsoding 风格）

专为喜欢 **Tsoding Daily** 风格（从零写有趣开源项目、看高手真实思考过程）的学习者设计。  
使用语言：**C 和 C++**  
核心方法：**多看、多敲、多改、多 push 到自己的 GitHub**

## 阶段 0：快速热身 & 补基础（1-2 周）

- 目标：熟练使用 C/C++ 写控制台程序、动态内存、简单数据结构
- 推荐资源：
  - javidx9（One Lone Coder）**Code-It-Yourself** 系列前几个短项目
    - Snake、Pong、Tetris 等控制台游戏
  - 操作方式：边看边敲代码，完成后自己添加功能（分数、难度、AI 等）

**建议**：如果你已经能独立写中等难度的控制台程序，可直接跳到阶段 1。

## 阶段 1：入门项目驱动，快速获得成就感（2-6 周）

目标：掌握窗口创建、输入处理、渲染循环、简单游戏逻辑。

**推荐顺序**：
1. **javidx9** 主力（强烈推荐）
   - Console Game Series
   - OlcPixelGameEngine 项目（轻量 2D 引擎）
   - 项目示例：Asteroids、Breakout、Doom-style 射线投射、平台跳跃游戏
2. **Tsoding Daily** 穿插观看
   - 他的短项目：Tetris、简单游戏、Raylib 项目等

**阶段目标**：
- 独立完成 3-5 个小游戏（Snake → Tetris → Flappy Bird → 简单射击游戏）
- 所有项目都上传到个人 GitHub，并尝试添加自己的功能

## 阶段 2：底层硬核，真正懂高手怎么弄（2-6 个月，核心阶段）

目标：深入理解内存管理、平台层、性能优化、无依赖从零实现。

**推荐顺序**（强烈建议按此顺序）：
1. **Handmade Hero**（Casey Muratori）—— 必看经典
   - 从第 1 集开始，跟写到约 100 集左右
   - 学习内容：Win32 平台层、手动内存分配、游戏循环、音频输入处理、实体系统
   - 语言风格：纯 C（兼容 C++）
2. **Bisqwit** 模拟器系列
   - NES 模拟器、终端模拟器等直播/录播
   - 学习低级位操作、周期精确模拟、性能优化技巧
3. **Tsoding Daily** 进阶项目
   - 编译器系列（Lisp / Brainfuck / Forth 解释器）
   - Raytracer、自定义 malloc 实现等

**阶段小目标**：
- Fork Handmade Hero 并添加新功能
- 独立完成一个 **Chip-8 模拟器**（经典底层入门项目）
- 尝试修改 Bisqwit 或 Tsoding 的开源代码

## 阶段 3：现代 C++ + 工业级架构（6 个月+）

目标：学习现代 C++ 特性与大型项目组织方式。

**推荐资源**：
- **The Cherno** 的 Hazel 游戏引擎系列
  - 学习 Vulkan/OpenGL、ECS 架构、事件系统、现代 C++（智能指针、模板等）
  - 代码开源，架构清晰

**阶段目标**：
- 使用现代 C++ 重构之前的手工项目（例如用 Hazel 风格重写 Tetris 或 Raytracer）
- 尝试做一个中型项目，例如：
  - 自己的小型游戏引擎（支持 2D/3D sprite + 物理）
  - 实用工具（Markdown 编辑器、文件搜索器、简单数据库）
  - 向开源项目贡献代码（raylib、Dear ImGui 等）

## 阶段 4：自由创作 & 长期习惯

- 自由选择有趣项目：自制编程语言、Web 服务器、AI 小玩具、游戏 Mod 等
- 持续观看：
  - Tsoding Daily 最新直播
  - Bisqwit 更新
  - The Cherno 新视频
- 加入社区：Handmade Network、r/cpp、Tsoding Discord
- 保持把所有项目开源，定期分享，接受反馈

## 总体建议与时间线（每周 10-20 小时）

- **0-1 月**：阶段 0 + 阶段 1（javidx9 + Tsoding 短项目）
- **1-4 月**：阶段 2（Handmade Hero → Bisqwit → Tsoding）
- **4-10 月**：阶段 3（The Cherno + 重构项目）
- **10 月以后**：阶段 4，自由创作

### 重要学习原则
- **不要只看**，一定要自己动手敲代码
- 每个项目都要 **fork / 从零重写 → 添加自己的功能 → push 到 GitHub**
- 遇到卡点时：暂停视频 → 自己思考 → Google/查文档 → 实在不行再继续看
- 定期回顾之前写的代码，尝试用新知识重构
